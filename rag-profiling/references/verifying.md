# 검증과 수정: 맞는지 · 읽히는지 · 이어지는지 · 고치기

문서에 무엇을 어떻게 적는지는 `reporting.md` 다. 이 파일은 **적어 놓은 것을 확인하고 고치는** 쪽이다.
검사가 세 종류인데 **서로 못 대신한다.**

```
맞는지    수치·분모·문서 간 일치.   검사기가 후보를 내고 사람이 판정한다
읽히는지  절 하나가 전달되는지.     검사기가 못 본다. 맥락 없는 검사자에게 절을 나눠 맡긴다
이어지는지 절과 절이 이야기가 되는지. 나눠 맡기면 못 잡는다. 한 사람이 전체를 순서대로 본다
```

순서는 `검사기 → 후보 판정 → 읽히는지 → 이음매 → 고치기 → 다시 읽기` 다.
**검사자는 사람이 아니라 역할 에이전트다.** 앞의 두 검사는 갈라 맡기고 이음매는 나누지 않는다.
누구에게 무엇을 어떻게 주는지(배분 규약 다섯 · 산출 경로 · 판정 3값)는 `orchestration.md` 가 정본이다.

## 검사기

```bash
# HTML 에서 본문 텍스트와 수치를 뽑는다. --claims 로 수치 목록 JSON 을 함께 낸다
python scripts/extract.py report.html -o out/report.txt --claims out/report.claims.json

# 수치 목록을 산출 JSON · 형제 문서와 대조한다. --peer 는 여러 번 줄 수 있다
python scripts/validate.py out/report.claims.json --sources out/ --peer out/other.claims.json
```

`reporting.md` 의 오류 8유형 중 넷을 잡는다.

| 검사 | 유형 |
|---|---|
| 모든 수치를 산출 JSON 과 대조 | **5** 재현 불가 · **8** 문서 간 불일치 |
| 같은 라벨의 값이 여럿인지 | **6** 같은 지표 다중 값 |
| 비율 옆 분모 표기 유무 | **1** 분모 미표기 |

**`--claims` 를 생략하지 않는다.** `validate.py` 는 `.txt` 도 받지만 그때는 그 자리에서
텍스트를 다시 파싱할 뿐이라, 무엇을 대조했는지가 아무 데도 남지 않는다.
`.claims.json` 은 수치 목록에 원본 HTML 의 sha256 을 함께 박아둔다.
문서가 바뀌었는데 옛 대조 결과를 그대로 믿는 일을 이 해시가 막는다.
5 유형은 산출 JSON 과의 대조 자체가 근거이므로 이 기록이 없으면 가장 먼저 약해진다.
`--peer` 에도 형제 문서의 `.claims.json` 을 넘긴다.

## 후보 판정

**검사기는 후보를 보고하는 것이지 판정이 아니다.** 오탐이 있다. 하나씩 원자료로 확인한다.

**유형으로 뭉개서 넘기지 않는다.** 여기서 가장 흔하게 실패한다.
후보가 스무 건 넘게 나오면 `대부분 표 안 수치라 열 머리가 분모 노릇을 한다` 처럼
**한 문장으로 묶어 넘기고 싶어진다.** 그러면 그 안에 섞인 진짜가 그대로 남는다.
실제 사례에서 1유형 후보 23건을 그렇게 넘겼고, 그중 하나를 **읽는 사람이 표를 보다가 잡아냈다.**
묶어서 판단했다는 것은 하나씩 안 봤다는 뜻이다.
전부 못 보겠으면 **몇 건을 왜 안 봤는지 적고 다음 바퀴로 넘긴다.** 조용히 지우지 않는다.

**많으면 나눠서 병렬로 본다.** 한 건씩 보는 것이 부담이라 뭉개게 되므로, 부담을 줄이는 쪽으로 푼다.
검사자에게는 **판정 기준과 그 코퍼스의 분모 목록**을 함께 준다. 없으면 각자 다른 잣대로 본다.
나머지 배분 방법은 `orchestration.md`.

## 읽히는지 검사

검사기는 **수치가 맞는지**만 본다. **읽고 이해되는지**는 안 본다. 그래서 따로 돌린다.
수치가 전부 맞고 분모도 붙었는데 안 읽히는 일이 실제로 있었다
(사례와 그때 뭘 잘못했는지는 `reporting.md` 의 `표 옆 주석`).

**쓴 사람은 이 검사를 못 한다.** 왜 그 판단을 했는지 이미 알기 때문에 읽으면 이해되는 것처럼 느낀다.
그래서 검사자에게 **문서만 준다. 대화 맥락도 앞 바퀴 기록도 주지 않는다.**
맥락을 주면 검사자도 쓴 사람과 같은 상태가 되어 검사가 성립하지 않는다.

**HTML 이 아니라 `extract.py` 로 뽑은 텍스트를 절 단위로 갈라 준다.**
읽기 부담을 줄이려는 것만이 아니다. **텍스트로 뽑으면 색·칸·위치로만 준 뜻이 전부 사라져서,
글자로 안 남긴 표시가 그 자리에서 드러난다**(`reporting.md` 의 `표시는 뜻이 있을 때만`).
문서 전체에서 열리는 것(용어 대응표 같은)은 절 담당과 상관없이 **전원에게 함께 준다.**
팝업 내용도 따로 뽑아 주되 **본문 없이 혼자 읽어** 무엇에 대한 것인지 아는지 묻는다.

절 단위로 갈라 병렬로 맡긴다. 물어볼 것은 다섯이다.

```
무엇   이 절의 판단을 네 말로 한 문장으로 옮겨라
왜     그렇게 정한 근거가 무엇이라고 적혀 있나.  숫자가 아니라 그 숫자가 왜 그 판단이 되는지
잃음   안 지키면 무엇을 잃는다고 적혀 있나
낱말   뜻을 모르고 지나간 것을 전부 적어라.  짐작해서 채우지 말고 모른다고 적어라
분모   비율이 나올 때 무엇 분의 무엇인지 알 수 있었나.  못 알아본 자리를 적어라
       역산해서 알아낸 것은 알아본 것이 아니다.  그것도 못 알아본 자리다
```

**답을 못 하면 문장이 아니라 구성이 문제다.** 고칠 곳이 정해져 있다.

| 못 답한 것 | 빠진 것 | 고칠 자리 |
|---|---|---|
| `무엇` | 판단이 추상적이다 | 실물 조각을 판단 **앞에** 놓는다 |
| `왜` | 근거가 값만 있고 연결이 없다 | 그 값이 왜 그 판단이 되는지 한 마디 |
| `잃음` | `안 그러면` 이 비었거나 추상적이다 | 앞의 실물이 어떻게 망가지는지로 되받는다 |
| 모르는 낱말이 나옴 | 도메인 용어를 안 풀었다 | 실물 자리에서 그 조각을 읽을 만큼만 푼다 |
| `분모` | 그 절에 분모가 없다 | 절 머리에 분모 줄을 세운다(`reporting.md` 의 `비율을 적을 때`) |

맡기고 받는 방법은 `orchestration.md` 그대로다. **이 검사자에게만 입력을 덜 준다.**

## 이음매 검사

위 `읽히는지 검사` 는 절을 하나씩 본다. 그래서 **절 사이가 끊긴 것은 구조상 못 잡는다.**
절마다 다 이해됐는데 문서 전체로는 이야기가 안 되는 일이 실제로 있었다.

**한 사람에게 문서 전체를 순서대로 준다.** 절을 나눠 맡기지 않는다. 나누면 이음매가 그 사이로 빠진다.
읽는 방식도 다르다. **본문을 다 읽는 게 아니라 절 제목과 첫 문단만 순서대로** 읽게 한다.

```
흐름   제목만 위에서 아래로 읽어 이야기가 되나.  안 되면 순서가 틀렸거나 제목이 항목명이다
받기   각 절이 앞 절의 결론을 이름 그대로 받나.  "앞에서 배운 것이 여기 왜 안 나오나" 가 나오면 끊긴 것이다
넘기기 각 절이 다음으로 넘길 것을 남기고 끝나나.  "그래서 뭐" 가 남는 절을 적어라
이름   같은 값이 절마다 다른 이름·다른 숫자로 나오는 자리를 적어라
```

**끊긴 자리는 대개 내용이 아니라 한 문장이 없는 것이다.** 실제 사례에서 앞 절의 분류와
뒤 절의 파일명이 같은 것이었는데 그 말이 없어서 끊겨 보였다. 재보니 이어지는 것이었다.
**그러니 끊겼다고 보고되면 먼저 정말 안 이어지는지 재고, 이어지면 잇는 문장을 넣는다.**

## 고칠 때

**고쳤다고 말하기 전에 파일을 다시 읽는다.**
스크립트로 여러 곳을 한 번에 고칠 때, 치환 하나가 어긋나 중간에 멈추면
**그 앞에서 성공한 치환까지 통째로 날아간다.** 파일 쓰기가 맨 끝에 한 번 있기 때문이다.
그런데 화면 출력만 보면 어디까지 됐는지 모른다.
실제 사례에서 이 일이 두 번 났고, 두 번 다 "고쳤다"고 말한 뒤 원문이 그대로 남아 있었다.

```
짜기    치환마다 성공 여부를 찍는다.  실패해도 나머지는 쓰이게 짠다(예외로 멈추지 않는다)
확인    끝나면 파일을 다시 읽어 옛 문구가 0건인지 센다.  화면 출력을 근거로 삼지 않는다
```

**고칠 때는 같은 층위를 전부 센다.** 하나만 바꿔 짝이 깨지면 안 고친 것만 못하다.
표의 한 칸을 고쳤으면 같은 표의 나머지 칸, 그 표를 설명하는 주석, 다른 절의 같은 수치까지 함께 본다.
**표의 행을 더하거나 뺐으면 그 표를 요약한 문장을 다시 센다.** 검사기가 못 잡는 자리다.
산출 JSON 에 없는 수치라 대조할 것이 없기 때문이다. 실제로 `채택 17건 중 실측 14건` 이
표를 직접 세니 `채택 13 · 실측 10` 이었다. 행이 바뀐 뒤 요약만 옛 값으로 남은 것이다(4유형).

**수치를 고칠 때는 그 값을 만든 코드를 읽고 인용한다.** 한 JSON 객체에 있다고 같은 모수가 아니다.
