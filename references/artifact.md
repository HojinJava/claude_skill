# 아티팩트: 렌더 환경과 게시

문서에 **무엇을 적는지**는 `narrative.md` · `reporting.md` 다. 이 파일은 그것을 **화면에 띄울 때** 걸리는 것이다.
아티팩트는 렌더 환경이 일반 브라우저와 다르다. 아래는 매번 걸린다.

---

## 환경 제약

- **CSP 가 외부 리소스를 전부 막는다.** 스타일시트 · 폰트 · 이미지 전부 인라인한다.
  외부 CSS 프레임워크는 못 쓴다. 그래서 가벼운 방법은 라이브러리가 아니라 **인라인 규칙 몇 줄**이다.
- **읽기 폭을 `ch` 로 제한하지 않는다.** 전각 문자는 값이 절반으로 먹혀 본문만 좁아진다.
  `text-wrap:balance` 도 같은 방향이라 본문에 쓰지 않는다.
- **iframe 이 콘텐츠 높이만큼 늘어나 내부 스크롤이 없다.**
  `sticky`/`fixed` 를 쓰려면 컨테이너에 높이를 주어 **스크롤 컨테이너를 직접 만든다.**
  이 컨테이너를 `.scroller` 라 부르고, 스크롤 위치를 읽는 코드는 전부 이것을 기준으로 삼는다.
- **중앙 정렬된 박스에 `overflow` 를 걸면 스크롤바가 화면 가운데에 뜬다.**
  스크롤은 전체 폭 컨테이너가 갖게 한다.
- **raw 앵커 스크롤이 동작하지 않는다.** JS 스크롤 핸들러를 쓴다.

## sticky 열 머리

컨테이너를 만든 뒤에도 세 가지로 깨진다. 셋이 겹쳐 나므로 함께 고친다.

```
위로 샌다    스크롤 컨테이너에 위쪽 여백이 있으면 sticky 는 그 여백 아래에 붙는다
            그 틈으로 지나가는 행이 열 머리 위에 비친다
            → 여백을 컨테이너에서 빼고 열 머리가 padding-top 으로 갖는다
밑줄이 뜬다  border-collapse:collapse 는 테두리를 표가 그려서 칸을 안 따라온다
            → border-collapse:separate + box-shadow:inset 0 -1px 0 로 밑줄을 칸이 갖게 한다
덮인다      z-index 를 안 주거나 낮게 주면 뒤 요소에 가린다. 배경도 반드시 불투명하게
```

## 목차의 현재 위치

절이 열 개를 넘으면 목차가 이동 수단으로만 남고 위치 감각을 못 준다.
스크롤에 따라 현재 절을 강조하면 목차가 **지도**가 된다.
`IntersectionObserver` 로 절을 관찰하고, 스크롤 핸들러로 매 프레임 계산하지 않는다.
**관찰자의 `root` 를 `.scroller` 로 지정한다.** 비워 두면 뷰포트를 기준으로 삼아 아무것도 안 걸린다.

## 구역 표시

박스 드로잉 문자(`┐ │ ┘`)로 테두리를 그리지 않는 이유와 대안은 `reporting.md` 의
`구조와 구역은 문자로 그리지 않는다`. 여기서는 그 대안을 어떻게 만드는지만 말한다.
`border-left` + 옅은 배경 + 작은 라벨이면 구역이 표시되고 어떤 폰트에서도 안 깨진다.

## 게시

**수정이 끝날 때마다 같은 URL 로 다시 게시한다. 지시를 기다리지 않는다.**
게시하지 않으면 상대가 보는 화면은 옛 버전이라 고친 것이 없는 것과 같다.

**바퀴가 돌아도 문서는 하나다.** 회차마다 새 파일을 만들면 같은 문서가 여러 벌 남고
(실제로 세 벌이 91~93% 겹쳤다) 어느 것이 현행인지 파일명으로 알 수 없다.
이력은 원장이 갖고 문서는 `LOOP n` 라벨로 흔적만 남긴다. **버전 번호를 쓰지 않는다.**
