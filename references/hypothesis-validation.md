# 가설화와 2차 교차 검증: 4단계

1차 측정은 **각 코퍼스 안에서 닫혀 있다.**
코퍼스를 잇는 주장, 파이프라인 뒤쪽에 걸린 주장은 측정 안 된 **가정**으로 남는다.
그 가정을 **가설로 명시하고 따로 검증한다.**

---

## 가설을 쓰는 법

**각 가설에 "틀렸을 때 무너지는 설계"를 적는다.** 검증 우선순위가 거기서 나온다.
이걸 안 적으면 재미있지만 아무것도 안 걸린 가설을 검증하게 된다.

| | 가설 | 틀렸을 때 무너지는 설계 |
|---|---|---|
| H1 | 참조 대상이 상대 코퍼스에 **실재한다** | 도달 경로 전체가 무너짐 · 검색이 다른 축으로 축소됨 |
| H2 | 참조가 특정 대상에 **몰린다** | 참조 횟수를 가중치로 못 씀 · 중요도 신호 소멸 |
| H3 | 하위 계층도 참조된다 | 인덱싱 우선순위 재조정 |
| H4 | 링크된 것이 **올바른 버전**이다 | 오염이 링크를 타고 그대로 전파 |

실제 사례에서 **H3 는 기각됐다**(하위 계층 참조 2.1%). 기각도 결과다.
교차 검증 없이는 "하위 계층이 전체의 57.6%" 라는 1차 수치만 보고 반대로 갔을 것이다.

---

## 측정의 엄밀성 규칙

> **패턴으로 개체를 만들어내지 않는다. 실재 목록에 대조해서만 인정한다.**

정규식으로 "이름처럼 생긴 것"을 뽑으면 존재하지 않는 대상이 링크로 잡힌다.

```
나쁨:  참조 문자열에서 정규식으로 이름을 추출 → 그걸 링크로 계상
좋음:  상대 코퍼스에서 (정규화 이름 → 하위 식별자 집합) 목록을 먼저 구축
       참조 문자열을 그 목록과 대조 → 실재하는 것만 링크로 인정
```

실제 사례에서 실재 이름 5,624개(별칭 포함) 목록을 만들어 대조했다.

---

## 나쁘게 나오면 기각 전에 실패 표본을 읽는다

**이 규칙 하나가 47.6% → 73.3% 를 만들었다.**

```
1차 측정 47.6%  →  절반이 미연결 → 가설 기각 직전
                 ↓
       실패 사례를 직접 확인 (층화 표본)
                 ↓
       원인 4종으로 갈림 · 그중 3종은 표기 문제(정규화로 해결 가능)
                 ↓
       보정 후 73.3%  ·  잔여 26.7% 는 코퍼스의 구조적 한계로 확인
```

측정값이 나쁘면 **측정이 틀렸을 가능성을 먼저 본다.**
표기 변종·정규화 누락·파서 버그가 대부분이다. 그걸 걷어낸 값이 진짜다.

**분모가 바뀐다.** 보정하면 대상 집합이 달라진다(실제 사례: 291,262 → 287,165).
보정 전후 분모를 **둘 다 적는다.** 안 적으면 다음 사람이 틀린 조합을 쓴다.

---

## 파서 버그는 측정 결과가 아니다

교차 검증에서 값이 이상하면 **자기 코드를 먼저 의심한다.**
실제 사례에서 발견된 것들:

- 헤딩 정규식의 공백 처리 누락
- 제목의 겹괄호를 못 넘김 (125건)
- 이스케이프된 마커를 놓침

**버그를 고치면 회귀 테스트로 남긴다.** 재현 절차 문서에
`다시 돌리기 전에 확인할 것` 목록을 만들고 거기 적는다. 안 적으면 다음 바퀴에 또 밟는다.

---

## 2차 측정 결과 기록 형식

```
가설 | 판정   | 값                    | 무엇이 바뀌었나
────┼───────┼──────────────────────┼────────────────────────
H1  | 성립   | 73.3% (287,165 중)    | 교차 검색 경로 유지
H3  | 기각   | 2.1%                 | 하위 계층 인덱싱 우선순위 하향
```

**기각한 가설을 지우지 않는다.** 왜 안 갔는지가 없으면 다음 사람이 같은 걸 다시 검토한다.
